**大家好，我是老刘**

又到了每月一度的跨平台框架盘点的时间，有朋友问老刘为啥不做跨平台框架选型的建议了？

一方面是因为技术选型这件事本身就不是纯粹的技术问题，而是要结合团队背景、项目情况，甚至是领导喜好等技术之外的因素做出综合选择。

另一方面则是因为随着AI时代的到来，原有的选型逻辑也有了一定的变化。比如有的规模比较大的厂商会自己部署后训练的模型，有的厂商有基于某个框架历史代码的知识库。这些因素进一步加剧了框架技术选型策略的碎片化。

所以老刘现在主要把各个主流框架的进展摆出来，然后略做点评。如果是人读这篇文章，那么可以对当前的跨平台有一个比较整体的认知。如果是AI读，也能帮助AI进行技术选择有一个参考。

好了，来看看11月的跨平台圈又有了哪些变化。

Flutter 3.50带来稳定的原生互操作，.NET 11结束RC阶段，RN 0.88.1接手稳定版，Kotlin 2.5.0也走到RC。版本一多，升级顺序更不能乱。

这篇文章按官方发布页整理到11月17日，给你一份可以直接执行的升级清单。

## 1. 十一月跨平台技术综述

11月跨平台圈的关键词是**正式版落地**与**迁移验证**。

**① Flutter**

3.50正式发布，原生互操作、Web和设计包都有大改动

11月11日，Flutter 3.50与Dart 3.14一起发布。FFIgen的Objective-C支持和JNIgen的Java/Kotlin支持进入稳定阶段，Dart调用原生API可以绕开平台通道。Material和Cupertino继续拆包，旧入口正式弃用。当前stable频道是**3.50.0**，官方更新日志暂未列出3.50.x hotfix。3.47系列另有**3.47.8证书安全修复**，生产项目继续执行大版本观察两个月策略，证书修复则按安全补丁单独评估。

**② React Native**

0.88.1成为当前稳定版，0.89开始清理旧架构

RN 0.88.0在10月15日发布，0.88.1于10月27日跟进。0.88默认切换到Web风格的事件分发，支持可变字体和iOS SceneDelegate，官方仍然把它列为无用户侧breaking changes的版本。11月发布的0.89 RC则开始删除旧架构API，升级跨度明显拉开。

**③ KMP**

2.5.0 RC发布，Swift Export进入Beta

Kotlin 2.5.0-Beta2在10月21日发布，2.5.0 RC在11月11日跟进，当前稳定版仍是**2.4.21**。2.5.0把未使用返回值检查器转正并默认启用，Swift Export进入Beta，还带来实验性的多平台`.kar`发布格式。

**④ uni-app x**

5.33补齐资源热更新和支付宝小程序，5.34集中修复

上期之后，uni-app x发布5.33.2026102401和5.34.2026102909。5.33增加Android/iOS蒸汽模式的wgt资源热更新、支付宝小程序、uasm插件和CSS动画，uvue脚本默认使用TypeScript。5.34继续修复编译器、Web、Android、iOS和鸿蒙问题。

**⑤ .NET MAUI**

.NET 11正式版发布，CoreCLR成为默认运行时

11月10日，.NET 11正式发布，属于支持两年的STS版本。MAUI默认切换到CoreCLR，XAML增量热重载以预览形式提供，Android Shell改用handler架构，Windows默认启用`CollectionView2`。这次升级要验证的内容比RC2时期更明确了。

## 2. Flutter 3.50正式发布，原生互操作进入稳定阶段

Flutter 3.50公告见<https://flutter.dev/blog/whats-new-in-flutter-3-50>

Flutter更新日志见<https://docs.flutter.dev/release/release-notes>

11月11日，**Flutter 3.50.0**发布，内置**Dart 3.14**。这次不是hotfix堆叠，原生互操作、Web构建、设计包和移动端工具链都有实质变化。

### 2.1 Dart可以直接调用原生API

FFIgen的Objective-C绑定和JNIgen的Java/Kotlin绑定正式进入稳定阶段。Dart可以通过FFI和JNI直接调用平台API，支持同步调用，也能在后台Isolate里执行。Pigeon新的原生互操作模式目前仍是预览。

做插件的团队可以少写一层平台通道序列化代码，但原生对象生命周期、线程和绑定生成配置也得自己管好。调用路径变短了，工程要求并没有消失。

### 2.2 WebAssembly和缓存部署继续补强

Safari 26.2+和Firefox 147+现在可以通过`web/flutter_bootstrap.js`选择启用WebAssembly。官方在重型Widget基准测试中给出的结果是帧率超过JavaScript模式的两倍，不过目前仍需手动配置，后续版本才会默认开启。

`flutter build web --web-content-hash`会给JS、WebAssembly和资源文件名加入内容哈希，同时更新`flutter_bootstrap.js`。带哈希的静态资源可以设置长期缓存，入口文件继续使用no-cache，发版后用户拿到旧资源的问题会好处理很多。

旧的`dart:html`、`dart:js`、`dart:js_util`和`package:js`已经进入弃用流程。团队可以用`--no-deprecated-js-interop`提前检查项目和依赖，为WebAssembly适配排雷。

### 2.3 Material和Cupertino旧入口正式弃用

`package:flutter/material.dart`、`package:flutter/cupertino.dart`及对应的本地化委托正式弃用。新项目默认引用独立的`material_ui`包，已有项目可以执行下面的命令迁移。

```bash
dart fix --apply --code=migrate_design_widgets
```

这项变化会碰到大量import。业务页面越多，越应该先跑自动迁移，再检查自定义主题、本地化委托和依赖包的兼容情况。

### 2.4 移动端升级要盯住这些变化

iOS触控调度调整后，官方实测60Hz设备减少16ms输入延迟，120Hz ProMotion设备减少8ms。iOS 27真机调试的白屏和偶发启动崩溃也得到修复，Xcode 27下重新支持从CLI截取真机画面。

Android release构建会忽略外部Intent传入的`route`、`dart_entrypoint`和`cached_engine_id`，同时拦截运行时引擎参数。深度链接保持支持，但依赖这些内部入口参数的调试或集成方案需要改法。

Flutter 3.50新建的Android项目默认使用AGP 9.3.1、Gradle 9.5.0和Java 17，compileSdk与targetSdk为API 36，minSdk为API 24。插件还要继续迁移到AGP Built-in Kotlin，旧KGP接入方式到AGP 10将无法构建。

### 2.5 Flutter 3.47.8单独处理证书信任问题

Dart官方安全公告见<https://github.com/dart-lang/sdk/security/advisories/GHSA-frr6-h895-5pxp>

2026年10月，eMudhra签发的8张中间CA证书因私钥生成强度不足被公开披露。攻击者如果能进入App与服务端之间的网络路径，可以利用这些私钥伪造TLS/HTTPS证书，实施中间人攻击。

这次受影响的是Android、Windows，以及尚未更新系统证书包的Linux环境。Web、iOS和macOS使用浏览器或Apple系统安全框架完成证书校验，不在此次影响范围内。

**Flutter 3.47.8**内置**Dart 3.13.7**，通过更新BoringSSL直接拒绝受影响的中间CA证书。Android 14及以上版本的`dart:io`还改为从可更新的Conscrypt APEX模块加载系统根证书，后续可以通过Google Play系统更新接收根证书撤销。

在Android、Windows和Linux上，`package:http`和`dio`通常都走`dart:io`，不能只看到浏览器和操作系统已经更新，就判断App已经安全。升级SDK后还要重新构建并发布，用户设备上的旧安装包仍然带着旧网络栈。涉及账号、支付或敏感数据的项目，需要结合网络暴露面和用户更新比例，一起评估线上旧版本的处理方式。

### 2.6 老刘点评

老刘对Flutter大版本的固定策略没变，**生产项目先观察两个月，再考虑升级**。3.50在11月11日发布，现在可以建测试分支、排查依赖和做技术验证，生产环境先不急着切换。观察到2027年1月，再根据hotfix质量、第三方插件适配和项目回归结果安排生产升级窗口。个人项目和技术爱好者可以提前体验3.50。

这两个月重点看三件事。

1. 早期用户反馈和hotfix修复情况。
2. 项目使用的第三方插件是否完成适配，尤其是原生互操作、Web旧JS库和设计包相关依赖。
3. 测试分支的Android、iOS和Web构建与回归是否稳定，别只看本机能不能跑起来。

**证书修复是观察两个月策略的例外。**仍在3.47系列，并且覆盖Android、Windows或Linux的项目，应按官方公告尽快评估3.47.8和重新发版，不要拿观察期当延迟安全修复的理由。已经升级3.50的项目也包含这项修复，同样需要重新构建发布才能覆盖线上用户。

官方这次还补齐了AI编程插件和package skills。插件包含Dart/Flutter MCP配置、专用Agent和热重载规则，pub.dev包也可以在顶层`skills/`目录附带技能。AI辅助开发开始进入Flutter官方工具链，团队可以拿测试项目试用，先别急着改所有人的工作流。

## 3. KMP 2.5.0 RC发布，Swift Export进入Beta

Kotlin 2.5.0 RC文档见<https://kotlinlang.org/docs/whatsnew-eap.html>

Kotlin发布页见<https://github.com/JetBrains/kotlin/releases>

10月21日发布的**2.5.0-Beta2**和11月11日发布的**2.5.0 RC**把2.5.0的轮廓补齐了。当前稳定版仍是**Kotlin 2.4.21**，2.5.0继续走预发布流程。

### 3.1 返回值检查器默认启用

未使用返回值检查器在2.5.0进入稳定状态并默认开启。以前调用函数后忽略返回值，很多场景只能靠Code Review发现，现在编译器可以直接给出检查。

实验性的full value classes允许一个值类包含多个属性，通过`-Xfull-value-classes`启用。它能自动生成`equals()`、`hashCode()`和`toString()`，但目前不提供`componentN()`和`copy()`，离业务项目普遍采用还有一段距离。

### 3.2 Swift Export换了Gradle DSL

Swift Export在2.5.0进入Beta。配置入口从`swiftExport {}`调整为`export { swift {} }`，声明的依赖会自动导出，不再要求逐个显式调用`export()`。

RC还修复了Swift package在Release构建中链接失败的问题。做iOS共享库的团队可以用RC验证导出和链接流程，生产项目继续等正式版更稳妥。

### 3.3 多平台库新增`.kar`发布格式

除JVM和Android外，多平台产物可以打包成单个`.kar`文件。它是经过XZ额外压缩的ZIP归档，新增target时不必持续增加发布文件数量。

官方文档给出的`cryptography-kotlin`案例中，整个多模块项目从7539个文件、91MB降到1036个文件、23MB。发布`.kar`目前仍是实验能力，但所有项目已经可以消费这种产物，主要影响库作者。

### 3.4 老刘点评

2.4.21继续作为生产项目的稳定选择，2.5.0 RC适合放进测试分支。重点验证返回值检查带来的新告警、Swift Export DSL和iOS链接，不要只跑Gradle sync。

工具链也要提前检查。Beta2日志把最低Gradle版本提高到8.14.x，最低AGP提高到8.8.2。RC文档还明确提高了编译器运行环境要求，JDK 17以下会报错，临时退出开关计划在2.5.20或2.6.0移除。

上期关注的BTA默认化，这次RC官方文档没有明确说明，我先不往下推断。月度盘点以已经写进官方文档的变化为准，没确认的内容不拿来指导升级。

## 4. React Native 0.88.1进入稳定维护，0.89开始清理旧架构

React Native 0.88公告见<https://reactnative.dev/blog/2026/10/19/react-native-0.88>

React Native发布页见<https://github.com/react/react-native/releases>

**RN 0.88.0**在10月15日发布，官方于10月19日发出版本介绍。10月27日，**0.88.1**发布，成为当前稳定版。11月4日和11月10日，0.89.0-rc.0与rc.1先后发布。

### 4.1 事件分发切换到Web模型

0.88默认通过W3C EventTarget API分发事件，事件沿捕获路径到达目标，再执行冒泡。原有`onPress`、`onLayout`等公开API保持不变，触摸响应系统也没有改。

官方明确说明0.88没有用户侧breaking changes。不过，直接读取事件内部实现或旧插件注册表的库需要重点回归，这类代码已经绕开公开API，不能只看应用层能否编译。

### 4.2 可变字体、ArrayBuffer和SceneDelegate一起落地

`Text`和`TextInput`在Android/iOS都支持`fontVariationSettings`，字符串和对象两种写法都能使用。Java TurboModule可以直接接收和返回`ArrayBuffer`，二进制数据不用再统一编码成字符串或数字数组。

iOS 27 SDK要求UIKit应用接入UIScene生命周期。RN 0.88新增SceneDelegate入口，同时保留AppDelegate兼容路径。当前支持仍限于单Scene，迁移时还要处理`Info.plist`、URL context和user activity转发。

### 4.3 0.88.1继续修构建和平台细节

0.88.1把iOS Release构建的C/C++/Objective-C优化等级从`-Os`调整为`-O2`，Yoga和glog也统一使用`-O2`。SwiftPM的生成配置改放到`ReactNativeSPM`目录，升级版本时不再反复修改`project.pbxproj`。

这个修补版还处理iOS 27状态栏、图片复用后显示旧图、SafeArea偏移，以及Android文字装饰和复用`Paint`时的测量问题。已经升到0.88.0的团队，可以直接评估0.88.1。

### 4.4 0.89 RC的迁移成本开始增加

0.89 RC在Android和iOS新架构中固定启用Bridgeless，删除一批旧架构入口和废弃API。`@react-native/community-cli-plugin`需要显式加入`devDependencies`，Community CLI要求21.x。

携带预生成JNI codegen的Android TurboModule库需要用0.89重新生成。iOS库的CocoaPods头文件搜索路径和Swift nullability标注也有调整。rc.1主要是WebSocket调试、Metro缓存和Android视图崩溃修复，改动规模已经收小。

### 4.5 老刘点评

还在0.87的业务项目，可以把0.88.1作为本期升级目标。先检查是否直接依赖RN事件内部实现，再验证iOS SceneDelegate和常用第三方库，公开API不变不代表整个依赖链没有适配成本。

0.89 RC更适合框架、原生模块和第三方库维护者提前验证。普通业务项目不用抢这个RC，等正式版和依赖库适配说明出来，升级成本会更容易算清楚。

## 5. uni-app x 5.33补齐资源热更新，5.34集中修复

uni-app x更新日志见<https://doc.dcloud.net.cn/uni-app-x/release.html>

上期之后，uni-app x连续上架**5.33.2026102401**和**5.34.2026102909**。截至11月17日，官方日志顶部仍是5.34，本月暂未出现更新构建。

### 5.1 蒸汽模式支持wgt资源热更新

5.33为Android和iOS蒸汽模式增加应用资源wgt热更新。需要快速更新应用内资源的团队，现在有了官方实现路径。

uvue脚本同时支持`lang="ts"`和`lang="js"`，在Web、App蒸汽模式和小程序平台默认使用TypeScript。需要注意，ts/js下不再支持uts专用对象，已有页面升级时要单独检查类型和编译产物。

### 5.2 支付宝小程序和uasm插件加入支持列表

5.33新增支付宝小程序支持，Web、App蒸汽模式和小程序平台新增uasm插件，App平台同时支持Node API。跨端覆盖范围又扩了一档。

蒸汽模式的CSS能力也在补齐，`animation`、`@keyframes`和`calc()`已经进入官方更新日志。Android端的腾讯地图、个推和阿里云实人认证SDK完成16KB内存页面大小适配。

### 5.3 5.34修复编译和多端显示问题

5.34没有列出新功能，集中修复`match-media`发行报错和Web端属性失效、Android蒸汽模式`textarea`长按选择、iOS横竖屏返回后的TabBar布局，以及鸿蒙`rich-text`和SVG图片显示。

iOS VDOM和鸿蒙VDOM还修复了5.31引入的uvue TypeScript文件未按uts编译问题。5.33已经修复升级Xcode 27后uts插件编译失败，但日志没有说云端打包环境已经切到Xcode 27，这两件事不能混在一起。

### 5.4 老刘点评

已经在5.33的团队，建议跟进5.34，修复项覆盖编译器和多个平台，升级目标比较清楚。

从5.26跨过来的项目要留出验证时间。wgt热更新、支付宝小程序和CSS动画都值得试用，uvue默认TypeScript则会直接影响现有代码。先跑完整编译，再检查uts专用对象、列表、富文本和主题切换，别只验证首页能否打开。

## 6. .NET MAUI随.NET 11正式落地，CoreCLR成为默认运行时

.NET 11公告见<https://devblogs.microsoft.com/dotnet/announcing-dotnet-11/>

.NET MAUI 11文档见<https://learn.microsoft.com/en-us/dotnet/maui/whats-new/dotnet-11?view=net-maui-11.0>

11月10日，**.NET 11正式版**发布，C# 15同步落地。.NET 11属于STS版本，支持周期为两年。MAUI有独立支持政策，不能直接把这两年等同于MAUI的支持时长。

### 6.1 CoreCLR成为默认运行时

.NET 11 MAUI在各平台默认使用CoreCLR，Mono仍然保留。Apple平台不允许JIT编译，运行时会使用预编译代码和解释器。Native AOT作为可选发布方式保留，Android支持仍处于实验阶段。

这次变化会影响调试、性能分析、热重载、裁剪和应用发布。使用原生依赖或自定义发布流程的项目，需要按实际发布模式重新测试。

### 6.2 XAML和原生控件继续调整

XAML Incremental Hot Reload在.NET 11中仍是预览功能，Debug构建默认开启。它支持更新运行中的页面和控件实例，也能处理部分结构性修改。

隐式XAML命名空间减少重复声明，Windows默认使用新的`CollectionView2` handler，Android Shell切换到handler架构。导航、自定义handler和集合控件都应该进入升级回归清单。

### 6.3 测试模板进入CLI工作流

Android、iOS、tvOS、macOS和Mac Catalyst新增测试项目模板，可以通过`dotnet test`在设备、模拟器或桌面目标上运行。模板使用Microsoft.Testing.Platform，设备测试开始接入统一的CLI流程。

可选的`Microsoft.Maui.Controls.Compatibility`包不再随.NET 11提供，仍引用它的项目需要先完成迁移。从RC升级时，也要把SDK、运行时、NuGet包和workload统一切到正式版本。

### 6.4 老刘点评

正式版发布不代表可以跳过迁移验证。CoreCLR默认化、Android Shell handler和Windows `CollectionView2`都碰到了运行路径，回归范围要比普通修补版大。

建议先用正式SDK建升级分支，把导航、自定义handler、裁剪发布和原生依赖跑通。已经基于RC2做评估的团队，还要重新核对正式版包版本，别保留一套RC SDK加正式版项目的混合环境。

### 老刘建议

1. **Flutter用户**

   生产项目继续执行大版本观察两个月策略，目前先用测试分支验证3.50，观察到2027年1月再决定生产升级窗口。仍在3.47系列的Android、Windows和Linux项目要单独评估3.47.8证书修复，升级后重新构建发版，安全修复不等待观察期。

2. **KMP用户**

   生产项目继续使用2.4.21。2.5.0 RC重点验证Swift Export、返回值检查和JDK 17环境，库作者可以额外评估`.kar`发布。

3. **RN用户**

   0.87项目可以评估0.88.1，重点回归事件相关第三方库和iOS SceneDelegate。0.89 RC留给测试分支和原生库维护者。

4. **uni-app x用户**

   5.33项目可以跟进5.34。跨版本升级要检查uvue默认TypeScript带来的影响，并完整验证uts插件和多端页面。

5. **MAUI用户**

   基于.NET 11正式版重新跑升级评估。CoreCLR、导航、自定义handler、裁剪发布和原生依赖都要覆盖，别沿用RC阶段的结论直接上线。

这个月的升级任务已经很清楚了。先选一个测试分支，把项目实际依赖的框架升级跑一遍，再决定生产环境什么时候跟进。你目前最关心哪个框架，升级时卡在哪一步？欢迎聊聊你的情况。
